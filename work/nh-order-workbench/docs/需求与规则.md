# NH 订单整理工作台：需求与规则

## 目标

每天导入一个或多个 Five Star Furniture PDF 订单文件，在浏览器本地提取需要的椅子产品，人工复核后导出 Excel。

## 已确认规则

- CUBA 系列始终排除。
- 只处理含 `DIN CHR`、`DIN CHAIR` 或 `BAR STOOL` 的椅子产品。
- 每个符合条件的产品独立生成一行。
- `ORIGINAL` 椅子进入 `NH portal order`。
- `CHANGE` 中数量大于 0 的椅子进入 `NH portal order`，类型保留为 `CHANGE`。
- `CHANGE` 中数量为 0 的椅子视为取消，整张对应 PDF 页面放入 `取消订单`。
- 餐桌、边几和其他非椅子产品不进入主表。
- 订单备注优先于产品描述；备注中的 Leather、Stain、FAB 覆盖描述字段。
- 产品名称和材料值通过版式结构、字段标签和上下文提取，不建立附件专用值名单。
- 导出前允许人工编辑；无法可靠提取的字段必须显示待确认提示。

## 输出字段

1. Order Number
2. Item Code
3. Cover
4. Stain
5. QTY
6. Customer name
7. Order date
8. FAB
9. TYPE

## 非范围

- 不上传 PDF 到服务器。
- 不使用 OCR 识别扫描件。
- 不处理与当前 Five Star Furniture 版式差异明显的其他供应商 PDF。
- 不自动替代人工确认低置信度字段。
- 不部署到公网或生产环境。

## 验收标准

- 两份样例 PDF 可同时导入。
- 样例应生成 14 条主表记录和 1 个取消订单页面。
- CUBA、餐桌和边几不会进入主表。
- 导出的 Excel 包含 `NH portal order` 与 `取消订单` 两个工作表。
- 表格字段可在导出前编辑。
- 页面在 375px 与桌面宽度下无阻塞性布局问题。
